# CustomClothing API — Сервис заказа кастомной одежды

Веб-API для управления процессом создания и продажи кастомной одежды. Система позволяет пользователям просматривать каталог готовых работ, заказывать существующие вещи или оставлять заявки на разработку индивидуального дизайна.

## Технологии

*   **Платформа:** .NET 10 (C# 13)
*   **База данных:** PostgreSQL
*   **ORM:** Entity Framework Core (Code First)
*   **Документация:** Swagger (OpenAPI) с поддержкой XML-комментариев и примеров
*   **Контейнеризация:** Docker (для БД)

---

## Структура базы данных (Сущности)

1.  **ClothingCategory (Категории):** Группировка одежды (Куртки, Футболки, Штаны и т.д.).
2.  **CompletedWork (Выполненные работы):** Портфолио мастера. Содержит флаг `IsPublic` для отображения в каталоге.
3.  **DesignRequest (Заявки на дизайн):** Пожелания клиентов на создание новой уникальной вещи.
4.  **Order (Заказы):** Таблица зафиксированных продаж (как готовых вещей, так и завершенных кастомных заявок).

---

## Основные DTO

*   `CompletedWorkDto`: Данные для отображения в каталоге (название, описание, категория).
*   `CreateDesignRequestDto`: Данные от пользователя для новой заявки (название, описание, имя, телефон, адрес, категория).
*   `CreateOrderDto`: Данные для покупки готовой вещи из каталога.
*   `FinalizeRequestDto`: Параметры для менеджера при переводе заявки в статус "Завершено".

---

## Эндпоинты API

### Каталог и категории
*   `GET /api/catalog` — Получить список всех публичных работ (портфолио).
*   `GET /api/categories` — Получить список доступных категорий одежды.

### Индивидуальные заявки (Design Requests)
*   `POST /api/request` — Оставить новую заявку на создание кастомного дизайна.
*   `POST /api/request/{id}/finalize` — (Менеджер) Завершить работу по заявке. Автоматически создает запись в каталоге и фиксирует новый заказ.

### Покупка готовых вещей
*   `POST /api/order` — Создать заказ на уже существующую вещь из каталога.

## Подготовка окружения и запуск

### 1. Запуск базы данных (PostgreSQL в Docker)
Выполните команду в терминале для запуска контейнера:

```bash
docker run --name clothing-postgres -e POSTGRES_USER=postgres -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=ClothingDb -p 5432:5432 -d postgres:latest
```

### 2. Настройка подключения
Убедитесь, что в файле `appsettings.json` указана корректная строка подключения:

```json
"ConnectionStrings": {
  "DefaultConnection": "Host=localhost;Port=5432;Database=ClothingDb;Username=postgres;Password=postgres"
}
```

### 3. Применение миграций
В папке проекта выполните команды для создания таблиц и наполнения базы начальными данными (Seed data):

```bash
dotnet ef database update
```

### 4. Запуск проекта
Запустите проект через IDE или через терминал:

```bash
dotnet run
```

После запуска Swagger будет доступен по адресу: `http://localhost:5000/swagger`.

## Особенности логики
- **Публичность:** В каталоге (`/api/catalog`) отображаются только те выполненные работы, у которых установлен флаг `IsPublic: true`.
- **Процесс обработки заявки:** Когда менеджер вызывает эндпоинт `finalize`, заявка переходит в статус `Completed`. На её основе создается объект в `CompletedWorks`, и информация о клиенте дублируется в таблицу `Orders` для истории продаж.
- **Безопасность данных:** Реализовано разделение на сущности БД и DTO для защиты внутренней структуры базы данных.
